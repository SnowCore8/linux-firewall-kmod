模块由两个并列子包组成，职责正交：

- `logger`：基于标准库 `log/slog` 的日志子系统。入口 `Init(cfg)` 把配置映射为 `options`，经 `buildSinks` 按 `LogDestination`（SYSLOG/JOURNAL/FILE/BOTH）构建 sink 集合；每个 sink 实现 `sink` 接口（`io.Writer` + `Close`），通过 `fanoutWriter` 并行写出且任一失败不阻断其余。格式选择由 `newHandler` 在 JSON handler（`json.go`，固定字段顺序 ts→level→msg→version→attrs，整行单次 Write）与 `slog.TextHandler` 之间切换。文件 sink (`file.go`) 使用 O_APPEND + 单锁实现按大小轮转（`<base>.<n>`，n 越大越旧），syslog/journald 分别尝试 unixgram/unix 套接字并带降级到 stderr 的最终兜底。另暴露 `SetLogFile`/`LogFilePath`（`atomic.Pointer[string]`）供日志查看器读取路径，以及无锁的 `LogThrottler` 用于高频路径节流。

- `telemetry`：内核链路的只读观测面，采用「单写多读」模式。`Store` 持有当前 `Snapshot`（`contract.StatsResponse` / `Rates` / `AnalysisResponse` / `Windows` / `Link`），写侧（internal/kernel 的事件泵）用 `sync.Mutex` 更新 `cur` 后通过 `atomic.Pointer[Snapshot]` 原子发布；读侧（HTTP API、诊断端点）调用 `Snapshot()` 无锁取副本，保证跨字段自洽。`rateHistory`（`rate_history.go`）与 `Ring`（`ring.go`）是独立的固定容量环形缓冲，因一次读取跨越多个槽位而各自加锁。EWMA 平滑委托给 `analysis.EWMASmoother`，`RouterCounters` 作为薄表切断对 `kernel` 包的循环依赖。

依赖方向：`logger` 仅依赖 `config`；`telemetry` 依赖 `analysis` 与 `contract`，不被 kernel 反向引用。
