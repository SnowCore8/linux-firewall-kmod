以 cmd/firewall-daemon/main.go 为组合根，按职责拆分为多子包并通过共享契约耦合：
- 数据面：ingest_pipeline(inotify/reader/splitter) → analysis_risk_engine(时间窗计数 + 风险向量衰减) → bans_and_whitelist(活跃封禁缓存) → kernel_ipc_transport(netlink 编解码 + reactor/consumer)，构成入站日志到内核封禁下发的单向流水线。
- 控制面：config_loader 解析 YAML/CLI/env 三路合并，经 runtime_supervisor 驱动 pipeline 执行体生命周期、文件热重载与信号处理；jail_management 在启动时编译 logparse.RuleSet 注入 ingest 管线。
- 观测面：logging_telemetry 提供结构化 JSON Lines 输出，kernel_ipc_transport 暴露内核链路遥测，http_api_server 通过 httpcontract 表统一暴露分析、封禁、配置、Jail、威胁情报等 REST/SSE 接口。
- 持久化：persistence(SQLite) 作为封禁事件、IP 信誉、攻击事件、风险向量的长期存储，由 threat_feeds 拉取的黑名单与 bans cache 共同构成判定输入。
- 边界契约：wire_contract 定义 netlink 消息二进制布局，httpcontract 声明 HTTP 路由与业务码，二者是各子模块对外交互的唯一稳定边界。
