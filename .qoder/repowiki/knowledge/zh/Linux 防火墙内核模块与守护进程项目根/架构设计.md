根目录通过顶层 Makefile 把五个子域串联成一条单向依赖链：contract/*.fwidl → contract/gen.py → kernel_module（C）+ daemon（Go）+ frontend（Vite/React），再由 build_scripts 产出 .deb，tests 用 pytest + Playwright 对三者做集成/E2E 验证。
- 契约是跨端唯一真相源：.fwidl 经 contract_generator 同时产出内核头、Go HTTP 绑定与前端 d.ts；Makefile 的 `contract-drift` / `contract-check` 目标在 CI 中比对生成物与实现，任何漂移都会阻断构建。
- 守护进程通过 go:embed 把 Vite 产物（frontend 子模块输出）内嵌进二进制，因此 `make daemon` 会先触发 `make frontend`，再把静态资源临时拷贝到 src/daemon/web_ui/static，编译后由 trap 清理。
- 内核模块使用 kbuild 外部模块机制，源码树保持零残留，中间产物全部落到 build/obj/<kernel-release>/tree，支持多版本与远程交叉编译（kmod-remote）。
- 安装路径受 `_guard_local_install` 守卫保护：非 DESTDIR 且未显式授权时拒绝直接写入本机根文件系统，强制走 scripts/deploy.sh 或 deb 包。
- CI 流水线由 `make ci` 六阶段驱动（环境→格式→契约→构建→测试→清理），统一调用 Go vet、clang-format、yamllint、pytest 与 playwright test。
