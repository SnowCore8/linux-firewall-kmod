模块由「单一真相源 + 生成器 + 多份校验器」三层构成：
- 真相源：`netlink.fwidl`（内核↔daemon 的 packed 字节布局）、`procfs.fwidl`（内核↔运维的命令文法）、`http.fwidl`（daemon↔前端的 REST/SSE 路由表 + JSON 形状 + 错误模型），三者语法不同但都经 `gen.py` 解析。
- 生成器：`gen.py` 把 IDL 解析为 `Contract`/`ProcFile`/`TextProtoContract` 等 AST，执行枚举/位标志/消息长度等静态校验后，向 `contract/generated/` 输出 C 头（`__packed` 结构体 + `_Static_assert`）、TS 接口与 `WIRE_SIZES`/`TAIL_LIMITS`、JSON 布局清单；HTTP 契约额外产出 Go 包 `httpcontract`（放在 `src/daemon/internal/httpcontract/` 内以通过 Go module 边界）。
- 校验器：`verify_layout.py` 三方比对（IDL 算出的布局 JSON vs Python 重解析生成头 vs C 编译器 sizeof/offsetof），并断言内核只消费生成头不手写报文结构；`verify_http.py` 逐项核对 daemon 的 routes.go/auth.go/sse.go/envelope.go 等源码与前端 TS 类型/端点，含缺口棘轮基线 `http_gap_baseline.txt`；`verify_procfs.py` 用锚点字符串核对 procfs 条目名、权限宏、key 格式符与 limit 常量。
依赖方向单向：ID → gen.py → generated/* → verify_* 读取 generated 与真实源码做第三方比对，校验器之间互不依赖。
