# 前端重写设计（Phase 3）

> 本文是 Phase 3 前端的**前瞻设计**：定义目标结构、必须遵守的冻结面，以及尚未落地的工作批次。
> 事实以仓库源码为准——`frontend/`（React 应用）、`src/daemon/web_ui/`（静态资源与嵌入）、
> `src/daemon/http_exporter/handler.rs`（路由与认证）、`contract/*.fwidl`（接口真相源）。
> 本文不复述逐文件实现，也不复盘被替换掉的旧前端。

相关内容：

- 三端重写的目标与验收口径、威胁模型：仓库根 `ITERATION-PLAN.md`
- 后端路由分层、SSE 约束、认证与信封语义：`../architecture/daemon.md`
- 接口真相源与门禁：`contract/http.fwidl`、`scripts/check_contract.sh`
- 构建、测试与 CI 接线：`building.md`、`testing.md`

## 决策记录

| 决策 | 取值 | 理由 |
|------|------|------|
| 技术栈 | React + TypeScript + Vite，UI 组件用 antd-mobile，路由用 react-router 的 hash 模式；具体版本以 `frontend/package.json` 为准 | 目标形态是手机浏览器上的运维控制台，组件库必须自带移动端交互（下拉刷新、无限滚动、触摸反馈），不必自造 |
| 路由模式 | **hash 路由** | 守护进程只对固定的几条页面路径返回 SPA 外壳，且没有 catch-all；history 路由下用户在子路径按刷新会被服务端 404。hash 路由永远只请求外壳本身，刷新与直达都安全 |
| 图表 | 不引入图表库，图表为手写 SVG 组件（见 `frontend/src/charts/`） | 图表类型固定、数据形状固定，引入库带来的体积与主题适配成本高于自研几何；自研也避免了图表库在移动端的指针事件改造 |
| 构建产物 | **不入库**（`src/daemon/web_ui/static/*` 在 `.gitignore` 内）；`make daemon` 先构建前端再编译 Rust | 产物是构建结果而非源码，入库会让每次前端改动产生巨量 diff，且容易与源码不同步 |
| 认证载体 | fetch 显式携带 `Authorization: Basic <base64(user:pass)>`；`EventSource` 用 `?access_token=<同值>` 查询参数 | SPA 外壳是公开路由，顶层文档永远不返回 401，浏览器原生认证弹窗因此**永不出现**；依赖原生认证的结果是页面能打开、接口全部 401，并把服务端暴力破解计数喂到锁定 |
| 实时数据 | 单条 SSE 连接（应用根部单例）承载增量，REST 只做兜底与首帧 | 路由切换不得重建连接；切页重连会丢增量并放大服务端连接数 |
| 白名单键 | 原样展示服务端返回的规范化键，前端既不剥离也不补全 `/prefix` | 键的形态是内核语义（见下文「CIDR 键形态」），前端自行改写等于制造第二套真相 |
| 威胁模型 | 入站单向防守 | 前端只呈现入站侧数据（封禁、白名单、速率、扫描/探测统计），不设计出站流量或外发行为视图 |
| 依赖方向 | 视图层不直接拼 URL、不直接 `fetch` | 端点集中在一处，才能在契约变更时一处修改、并被契约门禁核对 |

## 范围与验收

### 做什么

1. 把控制台做成**移动优先**的单页应用：仪表盘、封禁、白名单、DDoS、日志、Jail、设置，以及收纳二级页的「更多」。
2. 建立**一处分层的数据面**：端点、类型、信封解包、错误类型、SSE 单例、异步取数 hook。
3. 保持**服务端契约不变**地接入：静态资源经 `/static/*path`、实时数据经 `/api/v1/events`、写操作经受保护的 `/api/v1/*`。
4. 支持 PWA（清单 + Service Worker）在**安全上下文**下的安装。

### 不做什么

- 不改服务端契约的形状（路由、认证类、信封、业务码、SSE 事件集与上限）。需要变更时先改 `contract/http.fwidl`，再改两侧代码，并跑 `bash scripts/check_contract.sh`。
- 不引入图表库、不引入 UI 框架之外的组件库、不引入状态管理库（SSE 单例 + 局部状态够用）。
- 不做旧前端代码、类型或样式的复用；旧实现只作为「曾经有什么功能」的线索。

### 完成标准

- 三条门禁命令全绿（见「验收门槛」），且契约门禁把前端 `types.ts` / `endpoints.ts` 与契约核对通过。
- 手机视口下全部一级页与二级页可达，触摸目标不小于 44px，列表为卡片式而非表格。
- 所有取数与写操作都有 loading 与 toast 反馈，失败必须可见；不得留下空函数、`TODO` 或硬编码假数据。
- PWA 在安全上下文下可安装；非安全上下文下功能不受影响（这是被记录的约束，不是待修的缺陷）。

## 冻结面：服务端契约

### 静态资源与构建产物

守护进程用 `rust-embed` 把 `src/daemon/web_ui/static/` 嵌入二进制（`src/daemon/web_ui/mod.rs`），
页面外壳由 `render_dashboard()` 读嵌入的 `index.html` 返回，挂载点是 `<div id="root">`。
因此构建侧必须满足：

- Vite `base: '/static/'`，产物目录直接指向 `../src/daemon/web_ui/static`；
- 资源平铺输出、文件名固定（入口 `app.js`、样式 `style.css`），以便外壳引用稳定、Service Worker 可预测；
- 静态资源请求由 `GET /static/*path` 提供，MIME 按扩展名判定——扩展名与 MIME 的对应表以
  `web_ui::get_static_asset` 为准，**新增产物扩展名必须同时补该表**，否则会以
  `application/octet-stream` 下发。

构建配置与静态服务契约是一对：改动其中一侧必须同步另一侧，`frontend/vite.config.ts` 与
`src/daemon/web_ui/mod.rs` 的注释互相指认了这一点。

### 路由与认证分层

服务端把路由分成两组（`handler.rs::build_router`）：

| 组 | 认证 | 内容 |
|----|------|------|
| 公开 | 无 | SPA 外壳与页面路径、`/static/*path`、`/sw.js` |
| 受保护 | Basic Auth | `/metrics`、全部 `/api/v1/*`（认证中间件只挂在 API 路由上，探针不套认证） |

公开外壳**不含任何运行时数据**——数据一律经受保护的 API 取用，所以外壳公开不泄露状态，
浏览器也能直接加载页面子资源而不撞 401。这条分工是前端认证闸门的前提：外壳能打开不代表已认证，
前端必须自己判断有无令牌并渲染登录页。

`/` 会重定向到 `/dashboard`（保留查询串）。页面路径的完整清单以 `handler.rs` 的 `public_routes`
为准，前端路由表必须与它保持一致，新增页面路径要**先加服务端路由再改前端**。

### 信封与错误

`/api/v1/*` 的响应形状、业务码与 HTTP 状态码的对应、错误模型与安全头都由契约固定，
核对面在 `contract/verify_http.py`（`check_envelope` / `check_codes` / `check_errmodels` /
`check_headers`）。前端的实现纪律只有一条：**只有 HTTP 2xx 且业务码为成功值才算成功**，
其余一律抛出统一错误类型，把后端 `message` 带给调用方；非 JSON 响应回退为带状态码的通用消息。
视图不得直接判断返回码。

### SSE

| 项 | 值 | 出处 |
|----|-----|------|
| 事件流端点 | `GET /api/v1/events` | `contract/http.fwidl` |
| 事件名 | `connected` / `stats` / `bans` / `jails` / `rates` / `whitelist` | 同上 |
| 连接上限 | 契约常量（两条流各自独立） | `contract/generated/http_contract.rs` |
| 超限响应 | `503` | `src/daemon/api/sse.rs` |
| 连接上限查询 | `GET /api/v1/stats/sse-status`（分别上报两条流） | 同上 |

前端侧的硬要求：

- **单例**：Provider 挂在认证闸门之内、路由之外，只创建一条连接；路由切换不重建。
- **退避**：`EventSource` 自带的重连节奏不可控，故收到 `error` 主动关闭，按
  `delay = min(2^min(attempt,5), 30)` 秒调度下一次；每个连接周期设防重入标志，
  `onerror` 只处理一次，并用「当前连接对象 === 触发者」丢弃旧连接的迟到回调。
- **上限即停止**：重连第 2 次起先查 `sse-status`，服务端已满时进入 `connection_limit` 并
  **停止重连**——继续重试只会持续打满服务端日志，且永远不可能成功。
- **序列化按域增量**：服务端只推变化的域，前端按域覆盖快照，不做「每帧全量替换」。
- **仅 `events` 一条流**：日志流有独立上限与独立订阅者，用一条流的上限推断另一条是历史缺陷。

### CIDR 键形态（`10.0.0.1` 显示为 `10.0.0.1/32`）

白名单条目的键是内核语义的规范化结果：主机位清零、**恒带 `/prefix`**。这是内核把白名单存成
网络地址（`fw_addr_normalize`）的直接后果，daemon 侧只做同一套规范化，不再有第二套规则。

```text
# 归一化示例（前端原样展示右侧形态，不做任何改写）
10.0.0.5/24  →  10.0.0.0/24      # 主机位清零
10.0.0.1     →  10.0.0.1/32      # 裸 IPv4 地址补 /32
2001:db8::1  →  2001:db8::1/128  # 裸 IPv6 地址补 /128
```

因此：

- 界面上裸地址显示为带 `/32`（或 `/128`）的形态，**不是**显示错误，而是契约的直接结果；
  前端不得在渲染、复制、搜索匹配里剥离前缀。
- 新增/删除白名单时，请求路径上的 CIDR 段必须整体做 URL 段编码（`/` 与 IPv6 的 `:` 都要编码），
  否则删除请求会命中错误的路径层级。
- 输入侧只做**校验**（与后端解析规则一致），不做归一化：归一化是服务端的职责，
  前端归一化会在契约变更时变成第二套真相。

### 契约真相源与门禁

三端接口的真相源是 `contract/`。前端被门禁覆盖的部分：路由清单（`check_routes_frontend`）、
类型形状（`check_types_frontend`）、信封/业务码/错误模型/安全头/SSE 事件集。
`bash scripts/check_contract.sh` 会重新生成产物并逐项核对，**前端与契约不一致会导致门禁失败**。
这条门禁的存在意味着：契约修订不是「后端的事」——改契约必须同时让前端跟着编译通过。

## 目标结构（分层与归属）

分层按**依赖方向**划分，不按文件数量划分：上层可以依赖下层，下层不得反向引用。

| 层 | 职责 | 允许依赖 | 禁止 |
|----|------|---------|------|
| `api/` | 端点常量、请求类型、信封解包、认证令牌与请求头、统一错误 | 仅标准库与自身 | 禁止 import 任何视图/hook/组件 |
| `hooks/` | 取数状态、SSE 单例、主题、Toast、认证上下文 | `api/` | 禁止 import 视图 |
| `lib/` | 纯函数：格式化、校验、默认值 | 无 | 禁止产生副作用（网络、存储、DOM） |
| `components/` | 无业务语义的展示与外壳（外壳、页头、统计卡、空态、错误边界、命令面板） | `hooks/`、`lib/` | 禁止直接取数 |
| `charts/` | 手写 SVG 图表与配色 | `lib/` | 禁止直接取数、禁止引入图表库 |
| `views/` | 页面：组合取数与展示，承载交互 | 以上全部 | 禁止直接 `fetch`、禁止拼 URL |
| `styles/` | 设计令牌与移动端基线样式 | 无 | 禁止写具体页面的布局（页面样式随组件） |

两条结构性约束：

- **只有 `api/` 层知道 URL**。端点集中在 `api/endpoints.ts`，视图通过函数调用取数；
  这样契约门禁只需核对一处，路径拼接的编码错误也只需在一处防住。
- **Provider 组合顺序固定**：主题在最外（其令牌要覆盖 Toast 与弹层），Toast 在认证之外
  （登录反馈需要它），认证在应用之外（应用据此决定渲染登录页还是主界面），SSE 在**认证之内**
  （未认证时不得建立无令牌连接）。顺序不是风格问题，调整会破坏「未认证不发请求」这条不变量。

## 数据面

**首帧 → 增量**：页面挂载先用 REST 取一帧（`useAsync`），随后由 SSE 覆盖同域快照；
SSE 未连上或该域没推过数据时才回落到 REST。二者共用同一份类型与展示组件，
避免「实时路径」和「回落路径」渲染出两种样子。

**令牌生命周期**：令牌是 `base64(user:pass)`，来源有两处——URL 的 `?access_token=`
（供外部链接携带）与本次会话的会话存储。启动时先解析令牌再渲染任何请求方；
未持有令牌时只渲染登录页，**不挂载 SSE**。退出登录清空令牌与缓存。
令牌不写入本地持久存储：管理凭据不应在关闭标签页后仍留在设备上。

**超时**：写操作与扫描历史表的统计端点耗时差异大，客户端超时设为一个较宽的值
（`api/client.ts` 的 `REQUEST_TIMEOUT_MS`），超时抛可读错误，避免界面永久停在 loading。

## 交互面

- **移动优先**：卡片式列表而非表格；底部 TabBar 承载一级页，二级页收纳在「更多」之下并用页头返回；
  触摸目标不小于 44px。
- **状态可见**：每个异步操作都有 loading 与 toast 结果；错误信息必须出现在界面上
  （错误边界把异常降级为可见卡片，而不是白屏）。
- **破坏性操作二次确认**：解封、移出白名单、批量操作、采纳推荐都要先确认，
  并在确认文案里写清影响范围。
- **空态要说明原因**：数据退化（如可用维度不足以致无法作图）与「确实没有数据」是两种状态，
  不得合并成一句「暂无数据」。
- **离线与断流可见**：SSE 断开、重连中、服务端连接已满，三种状态都要在界面上可区分。

## PWA

- 清单与 Service Worker 由 Vite 输出到静态目录，但**注册地址是根路径 `/sw.js`**：
  脚本作用域由脚本 URL 决定，`/static/sw.js` 只能接管静态资源、无法接管页面导航，
  因此守护进程单独提供 `/sw.js` 并带 `Service-Worker-Allowed: /` 与 `no-cache`。
- 抓取策略：导航请求网络优先回退缓存外壳；`/static/*` 缓存优先；**`/api/*` 完全不拦截**
  ——实时数据一旦走缓存，界面会在无人察觉的情况下展示陈旧状态。
- **安全上下文限制（记录，不修）**：Service Worker 只在 HTTPS 或 localhost 下注册。
  经 `http://<局域网IP>:<port>` 访问时浏览器不暴露该 API、静默拒绝注册，「添加到主屏幕」不可用，
  但界面功能不受影响。这是浏览器硬约束，代码只降级不报错，文档如实记录。

### 3.B 遗留路由迁入时的前端零改动回归

现状：Phase 2 仍有一批分析类与日志类端点在旧 handler 里（清单是
`handler.rs::legacy_protected_routes()` 与 `contract/http.fwidl` 的差集），前端已经调用其中多项
（封禁详情与建议、速率历史与窗口、各类分布统计、日志分页与日志流、信誉与阈值建议等）。

要做：这些端点迁入 `api/` 时**只换 handler 归属**，路径、载荷、错误形状一律不动；
每次迁移后跑一遍前端回归（类型检查 + 契约门禁 + 受影响页面的 e2e）。

验收：迁移提交不包含 `frontend/` 的改动，且 `bash scripts/check_contract.sh` 与 e2e 仍全绿。

### 3.C 非安全上下文下的 PWA 行为固化

现状：限制已在文档与代码注释中说明，但缺可复现的验收步骤。

要做：给出一条可复现的验收记录——在 `http://<局域网IP>:<port>` 下确认 Service Worker 未注册、
控制台无未处理异常、各页面功能正常；并与 HTTPS/localhost 下的可安装性形成对照。

验收：记录中同时包含两种上下文的观察结果，且不把限制当作缺陷「修掉」。

### 3.D 前端架构文档补齐

现状：`docs/zh/architecture/` 只有内核模块、守护进程、数据流三篇，没有前端页；
页面拓扑、数据面与认证边界目前只存在于源码注释与设计文档里。

要做：补一篇面向运维与二次开发的前端架构文档，覆盖页面与路由映射、数据面（首帧 REST + SSE 增量）、
认证与令牌载体、PWA 边界，并与 `daemon.md` 的「路由分层」「SSE 约束」「信封与认证」互链，
避免两处各写一份。

验收：文档中的路由、事件名、连接上限全部指向契约或源码，不复制会漂移的数值。

## 验收门槛

```bash
# 1) 类型检查：前端类型与契约生成物必须同时通过
cd frontend && npm ci && npm run typecheck

# 2) 构建：产物落到守护进程的嵌入目录，文件名固定
cd frontend && npm run build:only

# 3) 编译守护进程：会顺带确认嵌入产物可被 rust-embed 找到
make daemon

# 4) 契约门禁：含前端 types.ts / endpoints.ts 与契约的逐项核对
bash scripts/check_contract.sh

# 5) 浏览器端到端：夹具（insmod + 起守护进程 + 等 /health）走 scripts/e2e-daemon.sh
sudo bash scripts/e2e-daemon.sh start
eval "$(bash scripts/e2e-daemon.sh env)" && npm run test:e2e
sudo bash scripts/e2e-daemon.sh stop
```

## 已知限制

- **PWA 只在安全上下文可用**（见「PWA」一节）：局域网明文访问下不可安装，功能不受影响。
- **`/api/*` 不缓存**：离线时实时数据不可用，界面显示断流状态而非旧数据。
- **服务端 SSE 连接有上限**：达到上限时前端停止重连并在界面标记，不静默重试。
- **分析类端点仍在旧 handler 里**：迁移进度见「待办批次 3.B」，前端不依赖归属、只依赖契约。

## 纪律

- **先契约后代码**：接口需要变更时先改 `contract/http.fwidl`，再改两侧实现，最后跑
  `bash scripts/check_contract.sh`；禁止先让前端贴着实际响应写死。
- **不交假货**：不得留空函数、`TODO`、硬编码假数据；错误不得空 `catch`；空态与退化态要区分。
- **文档指向源码**：涉及数量、上限、枚举值时不写死数值，指向契约或源码（本文即按此写）。
- **产物不入库**：`src/daemon/web_ui/static/*` 是构建结果，不提交。
